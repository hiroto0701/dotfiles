# 模試の復習帳を作る

## 概要

模試の誤答を、公式試験ガイドの分野ごとに「原理 → 覚える表 → 問題カード」の順で並べた HTML 1 ファイルにする。見た目と部品は `template.html` で固定し、集計は `parse_mock.py`、検査は `check_sheet.py` と `render_figs.py` で機械的に行う。以下 `<skill>` はこのスキルのディレクトリ。

## 新しく作るとき

1. **既存を確かめる。** 同じ試験の復習帳（`~/Desktop/*-mock-review.html`、メモリの `<略称>-exam-prep`）があれば新規に作らず、「解き直し・別の模試を足すとき」に進む。
2. **集計する。** `python3 -I <skill>/scripts/parse_mock.py <模試.md> --out <作業>/m1.json`
   - 得点、誤答、複数選択の取りこぼし、未回答、解説自身が採点キーを疑う問題が出る。数字はこの出力を使い、手で数えない。
   - Udemy 形式でなければ、同じ JSON 形（`n` `correct` `mine` `is_correct` `multi`）に自分で変換してから進む。
   - under-selected が出たら、まず書き出しが誤った選択を落としていないか疑う。udemy-to-notebooklm で 2026-11-11 より前に書き出した md は、複数選択で誤って選んだ選択肢が抜けている。
3. **公式の分野を取る。** 試験の公式ページと試験ガイドから、分野・配点・時間・問題数・言語・合格点を取る。ガイドが PDF なら WebFetch が保存したファイルを Read で読む。合格点が公表されていなければ「公表されていない」と書く。分野を自作しない。7 分野以上ならガイドの大分類で 6 つ以下にまとめる（色は `d1`〜`d6`）。
4. **分類する。** 正解した問題も含めた全問を、ガイドの小分野に振って `<作業>/m1-domains.json`（`{"1": "3.1", "2": "2.1", …}`）に書く。2 つにまたがる問題は、決め手になる知識が属する小分野に振る。続けて `parse_mock.py <模試.md> --domains <作業>/m1-domains.json --snippet m1` を実行すると、分野別の正答（`by domain`）と、HTML に埋める `<script type="application/json" id="mock-m1">` が出る。
5. **誤答をパターンに振る。** 下の「間違いのパターン」の判定順で、1 問に 1 つ。
6. **章ごとに書く。** scratchpad に `<試験>/parts/` を作り、`template.html` の `<style>` までを `00-head.html` にコピーし、章ごとに 1 ファイルずつ書いて連結する。章立ては「章立て」、カードは「カードの部品」に従う。`mock-m1` の script は `<!-- 模試ごとの答え -->` の位置に貼る。
7. **検査する。** `python3 -I <skill>/scripts/check_sheet.py <sheet.html>` を OK にする。次に `python3 -I <skill>/scripts/render_figs.py <sheet.html> <作業>/shots` を実行して PNG を読み、文字のはみ出しと重なりを1回で直す。
8. **渡す。** `~/Desktop/<略称>-mock-review.html` に置き、Artifact で private 公開する。公開前に artifact-design スキルを読むが、色・書体・テーマは `template.html` を優先する（ライト固定は本人の指定）。パスと URL を返す。
9. **記録する。** メモリに `<略称>-exam-prep` を作り、受験日、ファイルのパス、Artifact の URL、回ごとの得点を書いて、索引に 1 行足す。

## 解き直し・別の模試を足すとき

1. **正とするファイルを決める。** ユーザーがファイルを指定したらそれを正とし、最後に Desktop と Artifact をそれに揃える。指定がなければ Desktop のファイル。
2. **前回の答えを確かめる。** HTML の `mock-…` の script を探す。
   - **script がなく元の md があれば**、`parse_mock.py <元.md> --snippet m1` で作って、メインの `<script>` の直前に貼ってから進む。
   - **script も md もなければ**、全問の一覧の「自分」「正解」列を前回の答えとして読む（正解した問題は分からない）。
3. **同じ模試の解き直しなら** `parse_mock.py <新.md> --prev <sheet.html> --prev-id m1 --domains <作業>/m1-domains.json --snippet m1r2` で比べる。`m1-domains.json` がなければ、前回の `mock-m1` の `d` から作る。
   - `WARNING question text differs` が出た問題は、番号が同じでも別の問題（抜粋や番号の振り直し）なので比べない。全問に出たら、解き直しではなく別の模試として扱う。
   - `NOTE every compared answer is identical` が出たら、取り込み済みの回を渡された可能性がある。何を足すのかユーザーに確かめてから進む。
   - 誤答カードの見出しの `<span class="sp">` の直前に `<span class="chip r-ng">2回目 ×</span>` か `<span class="chip r-ok">2回目 ○</span>` を足す。
   - `.ans` の「決め手」の行の後に `<p class="row"><span class="lab">2回目</span><span>…</span></p>` を 1 行足し、選んだ記号と、何を見て直した／また外したかを書く。新しいカードは作らない。
   - 前回正解して今回間違えた問題だけ、新しいカードを作る。
   - **同じ選択肢で 2 回間違えた問題**は、パターン章の最優先の枠の直後に `<div class="sec" id="repeat">` で「× → ○」の表（問題・分野・2回とも選んだ答え・正解・型・次から）にし、目次からリンクする。
4. **別の模試なら** カード id を `m2-qK` にして、同じ分野の章に小分野順で足す。
5. **数字を更新する。** 前回の数字は消さず、回ごとに並べる。
   - hero に「2回目」の項目を足す。一部の問題だけ解き直したなら「抜粋 N 問」と書く。
   - 分野別の棒（`.acc`）は 1 回目のまま残す。全問を解き直したときだけ、分野・1回目・2回目の表を足す。
   - 全問の一覧に「2回目」の列を足し、解き直していない行は「—」にする。パターンの件数は回ごとに書く。
   - localStorage のキーは変えない（チェックが消える）。
6. **検査する。** `check_sheet.py` を OK にし、`render_figs.py <sheet.html> <作業>/shots --ids <変えたカードや章の id>` で変えた所を見る。
7. **渡して記録する。** Desktop のファイルと Artifact の両方を更新する。Artifact は既存の URL を `read` してから同じ URL に publish する。メモリの `<略称>-exam-prep` に回の結果を足す。

## 章立て

| 章 | 中身 |
|---|---|
| hero | 試験名、受験日（`data-exam` で残り日数）、得点、誤答数、最大の失点パターン |
| 試験の全体像 | 形式の表、分野と配点と自分の正答率（`.acc` の棒）、出題範囲を層で示す図1枚、問題文の読み方、「この言葉が出たらこれ」の表（落とした組み合わせに `hit`）。問題集が古い製品名を使うなら新旧の表。模試が 20 問未満なら「分野の割合は目安」と 1 行添える |
| 基礎用語 | ユーザーが分からないと言った領域の一般用語を「用語・意味・<製品>では」の3列で。関係する問題へリンク |
| 分野ごとの章 | ガイドの順。原理（主張の見出しと図）→ 覚える表（似た名前の比較）→ 間違えた問題のカード（小分野順）。誤答がない分野も章を残し、原理の段落と覚える表だけ置く |
| 間違いのパターン | 最優先のルールを1つ枠で示し、パターンごとに件数・問題リンク・「次から」 |
| 採点キーへの注意 | `parse_mock` が挙げた誤答のうち、解説が想定解を疑っているもの。本番での読み方を書く |
| 全問の一覧 | 問題番号順。分野・自分・正解・一行・型 |

## カードの部品

`template.html` の `<article class="q">` を複製し、次の部品をこの順に埋める。

1. 見出し：`演習N · QK`、小分野のチップ（分野色）、複数選択なら「2つ選択」チップ、「次は解ける」チェック（`id="done-mN-qK"` `data-q="mN-qK"`）
2. 問題文：要約。条件は1つも落とさず、制約語（最小権限、場所を問わず、同じ形式、2つ選択など）を `.kw` で囲む
3. 選択肢：全部。正解は `li.ok`、自分の答えは `li.mine`、両方なら両方のクラスとバッジ
4. 引っかかり：自分の選択肢が、要件のどこを満たしていないか
5. 決め手：正解を選ぶ根拠を1文
6. 補足：仕組みを2〜3文。仕様は公式ドキュメントで確かめたものだけ書く
7. 採点キー注：解説が想定解を疑っているときだけ
8. 参照：関係する図・表へのリンク

## 間違いのパターン

誤答は1問に1つ、上から順に判定して最初に当てはまったものにする。採点キー注のある問題も振る。どれにも当てはまらないときだけ試験固有のパターンを足す。

| 順 | 記号 | パターン | 判定 |
|---|---|---|---|
| 1 | A | 複数選択で相方を取り違えた | 複数選択で、1つ目は正解なのに2つ目を誤った（under-selected と unanswered もここ）。正解の2つは「外す＋与える」「人＋リソース」のように対になりやすい |
| 2 | D | 層の取り違え | ID・API・責任分担の問題を、ネットワークなど別の層の道具で解いた |
| 3 | C | 動詞の取り違え | 問題文の動詞と、選んだ選択肢の動作が違う（例: 検出と保護、権限と実績、緩和と修正、保管と実行） |
| 4 | B | 要件の片側だけ満たす選択肢を選んだ | 自分の選択肢を外す根拠が、問題文と選択肢の文面だけで読み取れる（例: 「同じ長さ」の条件と「形式保持」という名前） |
| 5 | E | 名前・仕様の細部 | 自分の選択肢を外すのに、製品や仕様の知識が要る（例: テーブル有効期限は表全体を消す、FW ルールに FQDN は書けない） |

## 図

- 1枚で1つの主張を示す。誤答の原因になった仕組みを描き、比較なら2案を並べて違う所を見せる。目安は誤答の論点ごとに1枚、全体像1枚、基礎用語に1〜3枚。
- `template.html` の CSS クラス（`bx-*` `ln-*` `t*` `c1`〜`c6` `mk-*`）だけで描き、色を足さない。marker の id は図ごとに変える。
- 箱の幅は文字数から見積もる。日本語は1文字≒文字サイズ（12px なら約12px）、英数字は約0.55倍。左右に14px 以上の余白を足す。
- 正答率は `.acc` の HTML の棒で描く。SVG のグラフにしない。
- figcaption の先頭に `図 D1-1` の番号、末尾に関係する問題へのリンクを置く。

## 決まりごと

- ページはライト固定。`template.html` の色・書体・部品を変えない（本人の学習資料はすべてライトで統一している）。
- 本文は日本語。1文1論点、能動態。
- 模試の解説と公式ドキュメントが食い違うときは公式を優先し、カードの採点キー注に書く。

## よくある間違い

| 間違い | 直し方 |
|---|---|
| 得点や件数を手で数えてずれる | `parse_mock.py` の出力を使う |
| 分野を問題の内容から自作する | 公式ガイドの分野と配点を使う |
| 同じ試験の復習帳があるのに新しく作る | 新規の手順1で確かめ、追加の手順に進む |
| 複数選択の失点が、個々の誤答に埋もれる | パターン A として数え、件数が多ければ最優先の枠に出す |
| B と E を「本人が知っていたか」で分けて、判断がぶれる | 文面だけで外せるか（B）、製品の知識が要るか（E）で分ける。本人の知識は推し量らない |
| 番号が同じだけの別の問題を比べる | `parse_mock` の WARNING が出た問題は比べない |
| カードの書き方が問題ごとにばらつく | 「カードの部品」の8つをこの順で埋める |
| 図の文字が箱からはみ出す | `render_figs.py` の PNG を見て直す |
| 解き直しで同じ問題のカードを増やす | 既存カードにチップと「2回目」の行を足す |
| 前回の md が消えていて比べられない | HTML 内の `mock-mN` を `--prev` に渡す |
| Desktop か Artifact の片方だけ更新する | 両方を更新する |
